# 문의 시트 브리지 (Apps Script)

인트라넷이 구글 시트(문의 DB)를 읽고, 영업이 수기로 적는 칸(담당자·단계 등)에 값을 쓰게 해 주는 스크립트다.
시트의 **편집자 권한만 있으면** 설정할 수 있다. 구글 클라우드 프로젝트도, 시트 공유 설정 변경도 필요 없다.

> 이 스크립트는 **설정하는 사람의 구글 계정 권한으로** 시트를 읽고 쓴다. 그 계정이 시트 접근을 잃으면 연동이 멈춘다.
> 스크립트는 시트 파일 안에 저장되므로 시트의 다른 편집자도 볼 수 있다(토큰 포함). 시트 주인에게 미리 알려 둘 것.

## 설정 순서

1. 문의 시트를 열고 **확장 프로그램 → Apps Script** 를 누른다.
2. 기본으로 있는 `Code.gs` 내용을 모두 지우고 이 폴더의 `Code.gs` 내용을 붙여 넣는다. 저장(Ctrl+S).
3. **토큰 만들기(버튼 한 번)**: 편집기 위쪽의 함수 선택 칸에서 `setupToken` 을 고르고 **실행**을 누른다.
   처음에는 권한 승인 화면이 나온다(계정 선택 → 승인, “확인되지 않은 앱”이 나오면 **고급 → 이동**).
   끝나면 아래쪽 **실행 로그**에 `TOKEN = …` 이 보인다. 이 값을 복사해 둔다(다시 실행하면 같은 값을 다시 보여 준다).
   **이 값은 대화창이나 메신저에 붙여 넣지 말 것.** Vercel 에만 넣는다.
   - (선택) 속성을 직접 넣고 싶으면 왼쪽 **프로젝트 설정(톱니바퀴)** → **스크립트 속성**에서 `TOKEN` 을 추가해도 된다.
   - (선택) `SHEET_NAME` : 데이터가 첫 번째 탭이 아니면 같은 곳에 속성으로 탭 이름을 넣는다.
   - (선택) `SPREADSHEET_ID` : 시트와 별개로 만든 독립 스크립트일 때만.
4. 오른쪽 위 **배포 → 새 배포** → 유형 **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** (인트라넷 서버가 구글 로그인 없이 호출해야 해서 필요하다. 토큰이 없으면 아무것도 돌려주지 않는다.)
   - **배포** → 권한 승인 화면이 나오면 계정을 고르고 승인한다(“확인되지 않은 앱” 안내가 나오면 **고급 → 이동**).
5. 배포가 끝나면 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)이 나온다.
6. Vercel → core-sales-intranet → Settings → Environment Variables 에 **직접** 입력한다(Production, Sensitive).
   | 이름 | 값 |
   | --- | --- |
   | `SHEET_SCRIPT_URL` | 위의 웹 앱 URL |
   | `SHEET_SCRIPT_TOKEN` | 3번에서 만든 `TOKEN` 과 같은 값 |
   | `LEADS_PASSCODE` | 영업이 인트라넷 리드 화면에 들어갈 때 쓰는 공용 비밀번호(새로 정한다) |
7. 재배포하면 리드 인박스가 시트 연동 모드로 바뀐다.

## 확인

- 웹 앱 URL을 브라우저로 열면 `{"ok":true,"service":"sheet-bridge"}` 가 보여야 한다(데이터는 나오지 않는다).
- 인트라넷 `/leads` 에 비밀번호 입력 화면이 나오고, 들어가면 시트의 리드가 보인다.
- 담당자를 바꾸면 시트의 `담당자` 칸이 바뀌고 `인트라넷_기록` 탭에 한 줄이 쌓인다.

## 코드를 고쳤을 때

Apps Script 는 코드를 저장해도 이미 배포된 웹 앱에는 반영되지 않는다. **배포 → 배포 관리 → 편집(연필) → 버전: 새 버전 → 배포** 를 해야 한다(URL은 그대로).

## 앱이 쓰는 칸 / 읽기만 하는 칸

- 쓰기 가능: 담당자, 단계, 가능성, 최근 연락일, 리터치 일정, 1차 상담 내용, 다음 액션 플랜, 계약 금액, 메모
- 읽기만: 날짜, 상호명, 연락처, 이메일, 서비스 구분, 유입 경로, 예산, 문의, 문의 종류 (자동 입력 칸)

## 문제가 생기면

| 증상 | 원인 |
| --- | --- |
| 인트라넷에서 `unauthorized` | `TOKEN` 과 `SHEET_SCRIPT_TOKEN` 이 다르다 |
| 쓰기가 `row_moved` 로 거절됨 | 시트에서 행을 정렬·삭제·삽입해서 그 행의 날짜/연락처가 달라졌다. 새로고침하면 해결 |
| 쓰기가 `conflict` 로 거절됨 | 다른 사람이 같은 칸을 먼저 고쳤다. 새로고침 후 다시 |
| 쓰기가 `formula` 로 거절됨 | 그 칸이 수식이다. 수식 칸은 건드리지 않는다 |
| 갑자기 모두 실패 | 스크립트를 배포한 계정이 시트 접근을 잃었거나, 코드를 고치고 새 버전 배포를 안 했다 |

## 코드를 고친 뒤 확인

쓰기 안전장치(토큰·쓸 수 있는 칸 제한·행 확인·충돌·수식 보호·기록)는 가짜 구글 환경에서 이 폴더의 `Code.gs` 를 그대로 실행해 검증한다.

```
node integrations/sheet-bridge/test/gas-test.cjs
```

가짜 환경은 구글이 동작하는 방식을 흉내 낸 것이라, 실제 시트에서의 동작(특히 `=`로 시작하는 값을 글자로 저장하는 부분)은 배포 후 한 번 직접 확인해야 한다.
